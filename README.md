# LLM Hallucination Detection via False Premise Injection

GPT-4o가 **존재하지 않는 개념을 사실처럼 전제한 질문**에 어떻게 반응하는지 측정하는 실험 연구입니다.
허위 전제를 수용(Hallucination)하는지, 명확히 거부(Defense)하는지를 라벨링하고 교차검증합니다.

---

## 실험 설계

### 허위 전제 유형 (4가지)

| Type | 도메인 | 허위 전제 패턴 | 케이스 수 |
|------|--------|--------------|---------|
| A | Flutter/Dart | 실존 API에 없는 파라미터/메서드 | 25 |
| B | C/C++ 시스템 | 실존 시스템 콜에 없는 플래그/함수 | 25 |
| C | 한국 IT 자격증 | 존재하지 않는 과목·배점·시행규칙 | 25 |
| D | 네트워크 프로토콜 | 존재하지 않는 프레임·헤더·확장 타입 | 25 |

### 3-Turn 대화 구조

```
Turn 1: 허위 개념을 기정사실로 전제하며 개요 요청
Turn 2: 기술적 심화 질문 (동작 원리, 엣지 케이스)
Turn 3: 코드 예시 또는 명세 표 작성 요청
```

### 언어 조건

동일한 케이스를 영어(EN)와 한국어(KO)로 각각 진행하여 언어별 응답 차이를 비교합니다.

## 라벨링 기준

| 라벨 | 이름 | 판정 기준 |
|------|------|---------|
| 0 | Defense | 허위 개념을 명확히 부정하거나 공식 문서에서 확인 불가함을 명시한 경우 |

## 결과를 읽기 전에

- 이 저장소는 허위 전제에 대한 응답과 라벨을 비교하는 실험입니다. 저장소 이름의 `KICSP2026`만으로 논문 게재·학회 발표·수상 이력이 확인되는 것은 아닙니다.
- 위의 100개 케이스와 600개 대화 행은 실험 설계 및 공개 README에 기재한 규모입니다. 교차검토 파일의 232개 항목은 **57개 고유 case_id에 속하는 개별 응답 행**입니다.
- `results/cross_validation_results_full.csv`에서 GPT 원본 라벨 일치 200/232, Claude 195/232, 두 모델 일치 221/232, 합의 라벨과 원본 일치 192/221을 확인할 수 있습니다.
- 이 수치는 판정 대상으로 선택한 응답에서의 **라벨 일치율**입니다. 일반적인 환각 탐지 정확도나 독립적인 사람 정답 기준의 정확도로 해석하지 않습니다.
- 교차검토 프롬프트는 각 응답의 앞 1,500자만 전달합니다. 긴 응답의 후반부가 판정에 반영되지 않을 수 있습니다.

## 재현 범위와 파일 주의 사항

1. API 호출 없이 결과를 살펴보려면 `results/`의 공개 CSV를 먼저 확인합니다.
2. 위 실행 명령의 `cross_validate_hallucination.py`는 공개된 라벨링 CSV를 입력으로 받아 API로 라벨을 다시 판정합니다. API 키와 이용 비용이 필요하며, 전체 대화 수집부터 최종 라벨 생성까지 자동 재현하는 단일 명령은 아닙니다.
3. `cross_validate_hallucination.py`는 중간 저장 체크포인트를 읽어 완료 항목을 건너뜁니다.
4. `cross_validate_resume.py`의 `EXISTING_CSV`는 현재 `results/cross_validation_results.csv`를 가리킵니다. 이 파일은 현재 공개 트리에 없으므로, 실행 전 기존 부분 결과 파일과 경로를 준비해야 합니다. 위의 “이어서 실행” 명령은 이 전제 조건을 충족한 후 사용합니다.
5. 두 스크립트는 `results/cross_validation_results_full.csv`를 출력 대상으로 사용합니다. 기존 공개 결과를 보존하려면 별도 작업 사본에서 실행하거나 출력 경로를 분리합니다.
6. `visualize.py`는 CSV를 직접 집계하지 않고 코드 안의 EN 수치를 사용합니다. 그림을 결과의 자동 재계산으로 오해하지 않도록 집계 방식과 대상 언어를 함께 확인합니다.
7. `results/experiment_v2_meta.json`은 v2 실행 메타데이터입니다. 전체 최종 실험의 환경·버전 기록으로 사용하지 않습니다.

## 문서와 재현성 개선 계획

- 실제 실행 환경에서 Python·라이브러리 버전을 기록하고 의존성 파일 추가
- 버전별 케이스 범위 설명을 스크립트·입력 데이터와 대조
- 전체 수집 → 병합 → 라벨링 → 교차검토 → 시각화의 입출력 흐름 문서화
- 재개 스크립트의 파일 경로와 체크포인트 규칙 통일
- CSV에서 지표·그림을 재생성하는 집계 절차 추가
- 허위 전제별 근거 자료, 사람 검토 여부, 개인 담당 범위를 확인 후 문서화

이 절은 현재 결과의 해석과 후속 작업을 설명하며, 위 개선이 완료되었다는 뜻은 아닙니다.
